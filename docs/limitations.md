# AtomVM ESP32-C5 の TCP 通信でわかっている制約

**対象環境:** AtomVM `v0.7.0-beta.0+git.8d3e051`、Seeed Studio XIAO ESP32-C5。
別のバージョンや機器で同じ挙動になるとは限りません。

## 何が起きるか

接続数や通信負荷を増やした際、AtomVM が回復可能なエラーを返す前に、
タイマーやコンソールが応答しなくなる現象を確認しました。
これは AVModbus の例外処理だけでは回復できない、ランタイム側の制約として調査しています。

また、複数の TCP 接続を閉じるときに `event_queue` などへの通知失敗が表示される場合があります。
この警告だけで、AVModbus のメモリリークとは判断できません。

## 安全に試すには

- サンプルの TCP リソース計測は、**実機で回復を確認した 1～4 接続**に制限しています。
  これはすべてのアプリケーションに対する安全な接続数の保証ではありません。
- メモリ使用量は、同じ基板・AtomVM・設定・負荷で比較してください。
- 未検証の接続数を試すと機器の再起動が必要になることがあります。通常の利用例では制限を解除しないでください。
- Modbus TCP は信頼できるネットワーク内で運用してください。相互認証 TLS には未対応です。

再現条件や調査時のログ・検証手順は、開発者向けの
[詳しい調査記録](development/atomvm-tcp-investigation.md) に残しています。
基準となる計測値は [リソース計測](development/resource-measurements.md) を参照してください。
